### 1-A5 生成結果 + トレーサビリティ対応表（US-A2 AC1/AC2 / FR-1.4）
```
+----------------------------------------------------------+
| 生成完了。ビルド(型チェック): PASS (型エラー0)            |
| 意図 → 生成物 対応表:                                     |

```
> ビルド/型チェック不合格時は生成失敗として扱い、品質ゲート(1-3)のテスト/型柱で検出。

### 1-3 ゲート実行（US-B1/US-D2 / FR-2, FR-6.4）— 3状態表現
```
+----------------------------------------------------------+
| 品質ゲート (fail-closed)                                  |
|  [x] 1. テスト          PASS  12/12  cov 84%             |
|  [!] 2. 静的解析・型    FAIL  type 2件 (src/api/task.ts) |
|  [~] 3. セキュリティ    PENDING (実行待ち)               |
|  [ ] 4. デプロイ可能性  - (未実行)                       |
|  == 不合格のため停止。AIが自動修正を試行(1/3) ==          |
+----------------------------------------------------------+
記号凡例: [x]=PASS  [!]=FAIL  [~]=PENDING/実行中  [ ]=未実行  [E]=ERROR
```
> a11y: 各行は「記号＋英大文字ステータス語＋詳細」の三重表現（色非依存, US-D2 AC1）。PENDING/未実行は決して PASS と誤認させない（US-D2 AC2）。

### 1-3b 自動修正ループの進行（US-B2 AC1/AC2/AC3 / FR-2.3）
```
+----------------------------------------------------------+
| 自動修正 試行 2/3 — 全4柱を再評価                        |
|  [x] 1.テスト  [x] 2.静的解析・型  [!] 3.セキュリティ    |
|  [x] 4.デプロイ可能性                                    |
|  結果: 部分合格(3/4) = 不合格扱い。次の試行へ → 3/3       |
+----------------------------------------------------------+
```
> 各試行は「修正→全4柱再評価」の1サイクル。部分合格(例:3/4)も**不合格**として明示し、PASS数を進捗バーに見せない（US-B2 AC3の誤認防止）。全4柱合格で初めて成功。

```
|   競合: package.json, src/index.ts                       |
|   対処: 別ディレクトリを指定するか、競合を解消してください |
```

```
+----------------------------------------------------------+
```

### 1-5e デプロイ失敗 + ロールバック（US-C2 AC3/AC4 / FR-4.3/4.4）
```
+----------------------------------------------------------+
| [!] デプロイ柱: FAIL — スタック作成に失敗                |
|   理由: IAM権限不足 (iam:CreateRole が拒否)              |
|   ロールバック: 部分作成リソースを自動削除しました        |
|     （自動不可時は手順を表示: cdk destroy <stack>）       |
|   fail-closed: 公開されていません                        |
|                    [ 再試行 (r) ]  [ 中断 (q) ]          |
+----------------------------------------------------------+
```
> デプロイ柱の終端状態を成功(1-5)/失敗+ロールバック(1-5e)で明示。operation phaseルール（ロールバック手順必須）に準拠。

## 面2: 参照アプリ Web UI（mid-fi, WCAG AA志向）

### 2-1 ログイン（US-C3 / FR-5.4）
```
+----------------------------+
| MyApp                      |  <- h1
| Email    [______________]  |  入力にlabel関連付け
| Password [______________]  |
|        [   Sign in   ]     |
| [!] メールまたはパスワードが|  <- role=alert(aria-live)
|     違います                |  失敗時のみ表示
+----------------------------+
```

### 2-2 一覧（US-C3）— 通常 / 空状態
```
通常:                              空状態:
+------------------------------+  +------------------------------+
| Tasks          [ + New Task ]|  | Tasks        [ + New Task ]  |
| [ ] Buy milk  due 6/22  >    |  |                              |
| [x] Report    done     >     |  |  まだタスクがありません       |
| [ ] Call      due 6/25  >    |  |  [ + 最初のタスクを作成 ]    |
+------------------------------+  +------------------------------+
```

### 2-3 詳細/編集 + 削除確認（US-C3 AC2/AC3 / FR-5.2/5.3）
```
+--------------------------------+   削除確認ダイアログ:
| < Back                         |   +--------------------------+
| Title  [ Buy milk__________ ]  |   | このタスクを削除しますか? |
| Status (o)Todo ( )Doing ( )Done|   |  [ キャンセル ] [ 削除 ] |
| Due    [ 2026-06-22 ]          |   +--------------------------+
|   [ Save ]   [ Delete ]        |
| [OK] 保存しました              |  <- 成功: role=status
| [!] 保存に失敗しました(再試行) |  <- 失敗: 入力値保持
+--------------------------------+
```

### 2-0 Web ローディング状態（F6 / 進行中フィードバック）
```
ログイン送信中:  [ Sign in... ](disabled, スピナー, aria-busy)
一覧読込中:      スケルトン行 x3 (aria-busy=true)
保存送信中:      [ Save... ](disabled) ＋ "送信中" (status)
```
> 長時間処理は disabled＋進行表示＋`aria-busy` で示し、二重送信を防ぐ。
