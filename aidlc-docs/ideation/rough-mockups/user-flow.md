## 主要フロー1: 雛形で本番品質アプリを生成する（中核体験）

```
[利用者] 意図を自然言語で入力
   |
   v
[AI] 意図を解析・要約 --> [利用者] 承認 or 編集
   |                              |
   |          編集を選択 --------+ (意図を修正して再解析へループ)
   v
[AI] コード生成（TSフルスタック）
   |
   v
[品質ゲート fail-closed]
   1.テスト -> 2.静的解析/型 -> 3.セキュリティ -> 4.デプロイ可能性
   |                |
   全合格           不合格 --> [AI] 自動修正(最大N回) --> 再チェック
   |                              |
   |                              失敗継続 --> [利用者]へエスカレーション
   |                                              |
   |             +--------------------------------+
   |             v
   |   [利用者] 次を選択:
   |     (a) 意図を修正して再実行 --> 意図解析へ戻る
   |     (b) 手動で修正して再投入 --> 品質ゲートへ戻る
   |     (c) 中断（生成物は保存、後で再開可能）
   v
[AWSデプロイ] --> 公開URLを提示 --> 本番品質アプリ完成
```

## 主要フロー2: 生成された参照アプリのエンドユーザー操作

```
[サインイン] --(成功)--> [タスク一覧] --+--> [新規作成] --> 一覧へ戻る
   |                                     |
   +--(失敗)--> エラー表示・再入力        +--> [詳細/編集] --+--> [保存(成功/失敗通知)] --> 一覧
                                                          +--> [削除] --> 確認ダイアログ --> 一覧
```

> skeletonでは認証はシード済みユーザー前提のスタブ。サインアップ/本格認証は B-8（Should-have）で追加。

## フローの設計意図

- **フロー1が本イニシアチブの主役**。利用者の操作は「意図入力」と「要所の承認」に集約し、生成・検証・デプロイはAIと自動ゲートが担う（人間の承認帯域に集中、team-assessment.mdと整合）。
- 品質ゲートは fail-closed。不合格はまずAIが自動修正し、継続失敗時のみ人間にエスカレーション（速度と品質の両立）。
- フロー2は「雛形が生成する型」の例示。詳細なインタラクション/状態は refined-mockups と functional-design で詰める。
