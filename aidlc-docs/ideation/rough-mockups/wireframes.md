## 面1: AI生成ワークフローのCLI/ターミナル体験（雛形そのものの「UI」）

利用者が意図を伝え、AIが生成し、4本柱の品質ゲートが fail-closed で回り、AWSへデプロイされる体験。

**入口・前提条件（初回）:** このCLIが製品の主入口。初回のみ次が必要 — ①インストール（`npm create aidlc-app` 相当）②AWS認証情報の設定（`aws configure` 済みの前提）③初回セットアップウィザード（リージョン/プロジェクト名）。2回目以降は意図入力から開始。

```
+--------------------------------------------------------------+
| $ npm create aidlc-app@latest                                |
| > 初回セットアップ: AWSリージョン [us-east-1]                |
|   AWS認証情報: OK (検出済み) / プロジェクト名 [myapp]        |
|   == セットアップ完了。以後は意図を入力してください ==       |
+--------------------------------------------------------------+
```
<!-- Text fallback (CLI入口): 初回はインストール+AWS認証情報確認+セットアップウィザード(リージョン/プロジェクト名)。以後は意図入力から開始。 -->

> CLIアクセシビリティnote: ターミナルUIのため見出し/ランドマークは非該当。代わりに — ステータスは記号(`[x]/[!]/[ ]`)＋テキストの二重表現（色のみに依存しない）、スクリーンリーダー向けに各ゲート結果を1行テキストで出力、キーボード操作（Enter承認/`e`編集）を明示。

```
+--------------------------------------------------------------+
| $ create-aidlc-app  "タスク管理アプリを作りたい"              |
|                                                              |
| > 意図を解析中... 意図ステートメントを確認します             |
|   - エンティティ: Task(title, status, dueDate)              |
|   - 画面: 一覧 / 詳細 / 作成                                 |
|   [Enter で承認 / e で編集]                                  |
|                                                              |
| > コード生成中 (AI)............ done                         |
|                                                              |
| > 品質ゲート (fail-closed):                                  |
|   [x] 1. テスト         12 passed / coverage 84%            |
|   [x] 2. 静的解析・型   lint 0 / typecheck OK               |
|   [x] 3. セキュリティ   vuln 0 / secrets 0 / SAST OK        |
|   [ ] 4. デプロイ可能性 ... デプロイ中(AWS)                  |
|                                                              |
| > すべて合格。 https://xxxx.cloudfront.net で確認できます    |
+--------------------------------------------------------------+
```
<!-- Text fallback: CLIで意図を入力→AIが意図を要約し承認を求める→コード生成→4本柱ゲートをチェックリスト表示(fail-closed)→全合格でAWSのURLを提示。 -->

ゲート不合格時（fail-closed の挙動）:


## 面2: 生成される参照アプリのWeb UI（薄い縦切りCRUD）

walking skeleton が生成する代表アプリのラフ画面。デザイン詳細は refined-mockups で詰める。

ログイン（skeletonではシード済みユーザー前提のスタブ）:
```
+----------------------------+
|        [ App Logo ]        |
|                            |
|  Email   [______________]  |
|  Pass    [______________]  |
|        [   Sign in   ]     |
|  認証失敗時: "メールまたは |
|  パスワードが違います" を表示|
+----------------------------+
```
> a11y note: h1=アプリ名(ロゴ近傍), landmark=main(中央フォーム), キーボード入口=Emailフィールドに初期フォーカス→TabでPass→Sign in。エラーは入力欄近傍にテキストで提示（aria-live）。

一覧（List）:
```
+--------------------------------------------+
| MyApp            user@example  [ Sign out ]|
+--------------------------------------------+
| Tasks                       [ + New Task ] |
| -----------------------------------------  |
| [ ] Buy milk         due 6/22   > 詳細     |
| [x] Write report     done       > 詳細     |
| [ ] Call client      due 6/25   > 詳細     |
+--------------------------------------------+
```
> a11y note: h1="Tasks", landmark=header(アプリ名/サインアウト)+main(リスト), キーボード入口="+ New Task"とリスト各行はTab順に並びEnterで詳細へ。状態は記号＋テキスト（色のみに依存しない）。

詳細/編集（Detail）:
```
+--------------------------------------------+
| < Back                                     |
| Title  [ Buy milk_______________ ]         |
| Status ( ) Todo  (o) Doing  ( ) Done       |
| Due    [ 2026-06-22 ]                       |
|        [ Save ]   [ Delete ]               |
| Save時: "保存しました" / 失敗時エラー表示  |
| Delete時: 確認ダイアログを挟む(破壊的操作) |
+--------------------------------------------+
```
> a11y note: h1=タスク名 or "Task detail", landmark=main(フォーム)+nav(Back), キーボード入口=Titleに初期フォーカス→Tabで各項目→Save。Deleteは確認を挟む。保存/失敗はaria-liveでテキスト通知。

> 破壊的操作・フィードバックの方針（決定）: **Deleteは確認ダイアログを必須**。保存成功/失敗はテキストで明示。確認ダイアログの文言・トースト詳細は refined-mockups に送る。

## デザイン原則（ラフ段階）

- ツールの主役は「ワークフロー体験」。画面美より、品質ゲートの透明性（何が合格/不合格か一目で分かる）を最優先。
- 参照アプリは意図的にミニマル。雛形が生成する「型」を見せるのが目的で、装飾は最小。
- アクセシビリティ（コントラスト・キーボード操作）は refined-mockups で具体化。
