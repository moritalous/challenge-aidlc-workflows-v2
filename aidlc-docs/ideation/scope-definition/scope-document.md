# Scope Document — AIネイティブ Webアプリ雛形

> Status: Draft (awaiting approval gate)
> Perspectives: aidlc-product-agent (lead), aidlc-delivery-agent
> Upstream: `intent-statement.md`, `feasibility-assessment.md`, `constraint-register.md`

## プロダクト定義（一文）

**「自然言語の意図から、完全AIでコードを生成し、4本柱の品質ゲート（テスト・静的解析/型・セキュリティ・デプロイ可能性）を fail-closed で必ず通過させて、AWS上に本番品質のフルスタックWebアプリを高速に立ち上げる雛形」**。

提供形態は **D: 組合せ** — ①スターターrepo（TSフルスタックの土台）②品質ガードレール（CI上の必須ゲート）③AI生成ワークフロー（意図→生成→検証）を1つの型として束ねる。

## スコープ境界 (In / Out)

### In Scope（今回のスコープ内）

- AI生成を導く**スターターテンプレート**（モダンTypeScriptフルスタック: フロント + API + DB）。
- **AI生成ワークフロー**: 自然言語の意図 → コード生成 → 自動検証 → デプロイの一連（walking skeletonで実証）。
- **品質ゲート4本柱**（すべて fail-closed で必須化）:
  1. 自動テスト（ユニット/統合/E2E）
  2. 静的解析・Lint・型チェック・フォーマット
  3. セキュリティ（依存脆弱性スキャン・シークレット検出・SAST・入力検証）
  4. デプロイ可能性（CIが通り、AWSへ実際にデプロイできる）
- **AWSサーバレス系デプロイ**の足回り（IaC含む、既定構成）。
- 利用ドキュメント（個人が使い始められる最小限）。

### Out of Scope（今回は対象外）

- 複数アプリ形態への一般化（モバイル、純フロント、API専用等） — まずフルスタック1構成に集中。
- 組織横展開のためのガバナンス/配布基盤（将来フェーズ）。
- 非エンジニア（市民開発者）向けの専用UI — 一次利用者は個人エンジニア。
- マルチクラウド対応 — AWS前提。
- 重い規制対応（PCI/HIPAA等の固有要件） — 現時点で未指定。

## MVP / Walking Skeleton 定義

**Q2=C に基づく最小スライス:** 「意図 → AI生成 → 品質ゲート4本柱通過 → AWSデプロイ」が**端から端まで1回転する**最小デモ。
- 薄い縦切り（例: 1リソースのCRUD相当）で良いが、**4本柱ゲートとAWSデプロイを必ず含む**点が肝。
- これにより中核テーゼ（速度×品質の両立）を最初に実証する（**リスクファースト**, Q4=A）。

## 優先順位付け方針

- **シーケンス: リスクファースト**。最大の不確実性（AI生成のばらつきを品質ゲートで吸収できるか）を walking skeleton で最初に潰す。
- 期限に紐づく機能は無し（Q5）。市場スピード重視で早期skeletonを優先。

## トレーサビリティ

- 本スコープは `intent-statement.md`（速度×品質、本番到達、TS+AWS、品質4本柱）と `constraint-register.md`（TC-1〜5, RC-1〜3）に直接トレースする。
- 提供形態Dと品質ゲート全必須化は `feasibility-assessment.md` の「fail-closedゲートで生成ばらつきを吸収」方針と整合。
