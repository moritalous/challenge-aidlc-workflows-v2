# Competitive Analysis — AIネイティブ Webアプリ雛形

> Status: Draft (awaiting approval gate) ／ Source: デスクリサーチ＋アナリスト評価
> Upstream: `intent-statement.md`（課題=速度と品質の両立、対象=個人→将来チーム、品質4本柱）
> 注: 製品の具体評価は公開情報に基づくアナリスト見解であり、価格・機能は変動しうる（assumption）。

本イニシアチブ（intent-statement.md の「速度と品質を型と自動ゲートで両立させる雛形」）が置かれる競争環境を3層で整理する。

## 1. AIアプリビルダー／バイブコーディング系（速度に強い）

| 製品 | 強み | 弱み（本イニシアチブ視点） | 価格モデル(概観) |
|------|------|----------------------------|------------------|
| bolt.new (StackBlitz) | ブラウザ内で即生成・実行、フルスタック | 本番運用向け品質ゲート(テスト/セキュリティ/CI)の内蔵は薄い | 無料枠＋トークン課金 |
| v0 (Vercel) | UI生成・Next.js親和、デプロイ容易 | UI偏重、テスト/セキュリティの自動担保は限定的 | 無料枠＋サブスク |
| Lovable | 非エンジニア寄りの高速生成 | 生成物の保守性・品質の再現性が課題 | サブスク |
| Replit Agent | 環境込みで動かせる、エージェント実行 | エンタープライズ品質ガードレールは別途 | サブスク/従量 |
| Cursor / Claude Code / Copilot Workspace | 既存リポでの強力なAIコーディング | 「雛形＋品質の型」までは利用者設計に依存 | 席課金/サブスク |
| Devin 等の自律エージェント | 自律的タスク遂行 | 品質保証の作り込み・運用は発展途上 | 席課金 |

**示唆:** この層は「速く作る」を満たすが、**「完全AI生成でも本番品質を自動で保証する型」** は各製品の主戦場ではない。ここが本イニシアチブの差別化ポイント。

## 2. スキャフォールド／スターター系（再現性に強い）

| 製品 | 強み | 弱み（本イニシアチブ視点） |
|------|------|----------------------------|
| create-t3-app | 型安全TSフルスタックの定番、構成が一貫 | AI生成前提の設計やAI向けガードレールは無い |
| create-next-app / Vercel Templates | 立ち上げが速い、エコシステム大 | 品質ゲート(テスト/セキュリティ/CI)は利用者任せ |
| AWS Amplify Gen2 | AWSネイティブなフルスタック、型駆動 | 「AIに従わせる型」「自動品質ゲート」は範囲外 |
| Nx / Yeoman | 規約・ジェネレータで再現性 | バイブ開発のスピード体験・AI統合は弱い |

**示唆:** 構造の再現性は提供するが、**「AIが生成する」前提と「品質を強制するガードレール」を統合**していない。本イニシアチブはこの2点を最初から織り込む。

## 3. 品質ガードレール系（単体ツール群）

CI/CD（GitHub Actions 等）、Lint/フォーマッタ（ESLint/Prettier/Biome）、型（TypeScript）、テスト（Vitest/Jest/Playwright）、SAST・依存脆弱性・シークレット検出（CodeQL/Trivy/gitleaks 等）。

**示唆:** 個々は成熟。しかし**「AI生成フローに最初から組み込まれ、合格しないと進めない統合された型」**としてパッケージ化した既製品は少ない。本イニシアチブの中核価値はこの統合とオーケストレーション。

## 競争ポジショニング（まとめ）

- **Table-stakes（当然視される機能）:** 高速なコード生成、動くプレビュー、モダンスタック、容易なデプロイ。
- **差別化（本イニシアチブの主張）:** 「完全AI生成でも本番品質を自動担保する雛形」— 速度（層1）×再現性（層2）×品質ゲート（層3）を**1つの型に統合**し、AIが従いやすい合格基準として明文化する点。
- **直接競合の空白:** 「バイブの速度」と「本番品質の自動保証」を同時に、AI生成前提で型化した製品は現状手薄（assumption）。ここが参入機会。
